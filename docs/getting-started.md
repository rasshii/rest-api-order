# 始めるための手順

注文 API を使ってアプリを作る人が、サーバーの実装を待たずに、仕様から動かしたモックを相手に作り始めるための手順です。モックは [Prism](https://github.com/stoplightio/prism) で、`openapi/` の仕様から応答を返します。

## 要るもの

- Node.js 26 と Git と curl
- 画面で呼ぶなら、[Bruno](https://www.usebruno.com/) のアプリ (コレクションは `bruno/` にあります)

## モックを起動する

```bash
git clone https://github.com/rasshii/rest-api-order.git
cd rest-api-order
npm ci
npm run mock
```

`npm run mock` は、仕様を `dist/openapi.yaml` に束ねてから、`http://127.0.0.1:3904` でモックを起動します。モックは、仕様の例 (`openapi/components/examples/`) を応答に返します。

別の端末で、注文し、返った注文 ID で注文を確かめます。商品 ID は、下の「例の商品 ID」の表のものです。

```bash
curl -s -i http://127.0.0.1:3904/orders \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, application/problem+json' \
  -d '{"contactEmail": "taro.test@example.com", "lines": [{"productId": "01a0f4c2-c400-7a11-8b52-3c9d0e1f2a34", "quantity": 2}, {"productId": "01a0f4c2-c7e8-7b22-a963-4dae1f203b45", "quantity": 1}]}'
curl -s -i http://127.0.0.1:3904/orders/01a194b4-978e-7c3a-9f21-6d4b8e2a1c05 \
  -H 'Accept: application/json, application/problem+json'
```

1 つ目は 201 と `Location`・注文の表現を、2 つ目は 200 と注文の表現を返します。モックは注文を作らず覚えないので、どちらも仕様の例を返し、注文 ID も例の値です。注文 ID によって中身が変わるのは、サーバーを実装してからです。

応答の値を毎回作る形のモックは `npm run mock:dynamic` (`http://127.0.0.1:3905`) です。値は仕様のスキーマから作るので、例の値に頼らずに画面が動くかを確かめるのに使います。ただし、作った値が仕様に合うとは限りません (注文の表現の注文日時は、仕様の pattern に合わない値になります)。仕様に合わない所は、応答の `sl-violations` ヘッダに出ます。

## 返す応答を選ぶ

モックは、`Prefer` ヘッダで返す応答を選べます。

| ヘッダ | 返す応答 |
| --- | --- |
| `Prefer: code=404` | そのステータスコードの、仕様の最初の例 |
| `Prefer: code=400, example=insufficient-inventory` | そのステータスコードの、その名前の例 |

`Prefer` を付けるときは、`Accept` に、仕様が勧める `application/json, application/problem+json` を送ってください。`application/json` だけを送ると、モックは誤りの応答 (`application/problem+json`) を選べません。仕様に合うリクエストでは、`code` だけなら成功の応答に戻り、成功の応答に無い名前の `example` も付けると Prism の 500 になります。

## Bruno で呼ぶ

`bruno/` は、受け入れ条件 (`docs/requirements/stories.md`) のうち、モックで確かめられるものを 1 つずつリクエストにしたコレクションです。モックを起動したまま、別の端末で回します。

```bash
npm run bruno:mock
```

Bruno のアプリでは、`bruno/` のフォルダをコレクションとして開き、環境に `mock` を選びます。

## Swagger UI で呼ぶ

```bash
npm run docs:swagger
```

`http://localhost:3903` を開き、Servers で「モック (npm run mock)」を選ぶと、Try it out のリクエストがモックへ届きます。もう 1 つの `/` は Swagger UI を配っているサーバー自身を指し、そこに注文の API はありません。モックは別のオリジン (ポートが違う) なので、ブラウザは CORS の確かめをします。Prism は既定で、どのオリジンの画面にも応答を読ませるヘッダを付けます。

## 受け入れ条件とモック

モックは状態を持たず、仕様のスキーマで断れる誤りだけを見分けます。在庫・登録された商品・注文の有無は見ないので、それを結果にする受け入れ条件はモックで確かめられません。在庫が足りないこと・商品が登録されていないこと・注文が無いことは、サーバーを実装してから API で確かめます。在庫が減ること・変わらないことは、1 周目の API に在庫を読む操作が無いので、API では確かめられず、実装のテストで確かめます。

| 受け入れ条件 | Bruno のリクエスト | モックで確かめられないこと |
| --- | --- | --- |
| 在庫のある商品を注文すると、注文が受け付けられる | `bruno/place-order/accepted.yml` | 在庫が減ること (API に在庫を読む操作が無く、実装のテストで確かめる) |
| 在庫より多い数量を頼むと、注文は受け付けられない | — | 在庫が足りないこと (モックは在庫を持たず、形の正しい注文を受け付ける)。在庫が変わらないことは実装のテストで確かめる |
| 一部の商品の在庫が足りないと、注文全体が受け付けられない | — | 在庫が足りないこと (同上)。在庫が変わらないことは実装のテストで確かめる |
| 登録されていない商品を頼むと、注文は受け付けられない | — | 商品が登録されていないこと (モックは商品を持たない)。在庫が変わらないことは実装のテストで確かめる |
| 数量が 1 より小さい注文明細があると、注文は受け付けられない | `bruno/place-order/quantity-zero.yml` | どの注文明細の数量が誤りか (モックは誤りの中身によらず、仕様の最初の例を返す) |
| 注文明細が 1 つも無いと、注文は受け付けられない | `bruno/place-order/no-lines.yml` | 誤りが注文明細の無いことだと分かること (同上) |
| 同じ商品の注文明細が 2 つあると、注文は受け付けられない | — | 同じ商品の重なり (仕様のスキーマで書けない決まりなので、モックは注文を受け付ける)。在庫が変わらないことは実装のテストで確かめる |
| 連絡先メールアドレスが無いと、注文は受け付けられない | `bruno/place-order/no-contact-email.yml` | 誤りが連絡先メールアドレスの無いことだと分かること (同上) |
| 連絡先メールアドレスの形が正しくないと、注文は受け付けられない | `bruno/place-order/invalid-contact-email.yml` | 誤りが連絡先メールアドレスの形だと分かること (同上) |
| 受け付けた注文を、注文 ID で確かめられる | `bruno/get-order/accepted-order.yml` | 確かめた注文が、受け付けた注文であること (モックはどの注文 ID にも同じ例を返す)。注文日時が受け付けた時刻であること (リクエストは注文日時の形だけを確かめる) |
| 無い注文 ID では、注文が見つからない | — | 注文が無いこと (モックはどの注文 ID にも注文の例を返す) |

## 例の商品 ID

受け入れ条件の前提の商品と、仕様の例が使う商品 ID の対応です。1 周目の API には商品を探す操作が無いので、購入者は商品 ID を API の外から知っているものとします。前提の商品をこの商品 ID で登録すれば、仕様の例と Bruno のリクエストを、実装したサーバーにもそのまま使えます。

| 商品 | 商品 ID |
| --- | --- |
| りんご | `01a0f4c2-c400-7a11-8b52-3c9d0e1f2a34` |
| 保存容器 | `01a0f4c2-c7e8-7b22-a963-4dae1f203b45` |
| 登録されていない商品 | `01a0f4c2-d1a0-7c33-b874-5ebf20314c56` |
