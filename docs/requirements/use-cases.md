# ユースケース

ユースケースは、主アクターが目的を果たすまでの流れを、システムとのやり取りの順に書く。名前は主アクターの目的にする。

- **主な流れ**: うまくいくときの手順を、番号を振って書く
- **別の流れ**: 主な流れのどの手順で何が起きたら、どう進むかを書く。`4a` は手順 4 の別の流れ
- **事後条件**: 成功したときに成り立っていること
- **失敗したときの保証**: 目的を果たせなかったときにも成り立っていること

## ユースケース: 注文する

| 項目 | 内容 |
| --- | --- |
| 主アクター | 購入者 |
| 事前条件 | 商品と在庫が登録されている |
| 事後条件 | 注文が受付の状態で記録され、注文した数量だけ在庫が減っている |
| 失敗したときの保証 | 注文は記録されず、在庫は変わらない |

### 主な流れ

1. 購入者が、商品と数量の組と、連絡先メールアドレスを送る
2. システムが、注文明細が 1 つ以上あり、どの数量も 1 以上で、連絡先メールアドレスがメールアドレスの形であることを確かめる
3. システムが、どの商品も登録されていることを確かめる
4. システムが、どの商品も在庫が数量以上あることを確かめる
5. システムが、商品の今の価格を単価として注文明細に写し、合計と消費税額を求める
6. システムが、在庫を引き当て、注文を受付の状態で記録する
7. システムが、注文 ID と注文の内容を購入者に返す

### 別の流れ

- **2a** 注文明細が無い、数量が 1 より小さい、連絡先メールアドレスが無いか形が正しくない: システムは注文を記録せず、誤りのある項目を返す
- **3a** 登録されていない商品がある: システムは注文を記録せず、その商品を返す
- **4a** 在庫が数量より少ない商品がある: システムは注文を記録せず、どの商品の在庫も変えず、在庫が足りない商品を返す。一部の商品だけが足りないときも、注文全体を断る

## ユースケース: 注文を確かめる

| 項目 | 内容 |
| --- | --- |
| 主アクター | 購入者 |
| 事前条件 | 購入者が注文 ID を持っている |
| 事後条件 | 何も変わらない |
| 失敗したときの保証 | 何も変わらない |

### 主な流れ

1. 購入者が、注文 ID を送る
2. システムが、その注文 ID の注文を探す
3. システムが、注文の状態・注文明細・合計・消費税額・連絡先メールアドレスを返す

### 別の流れ

- **2a** その注文 ID の注文が無い: システムは、注文が見つからないことを返す
